📊 各组件调用情况分析
1. TokenTracker （Token 追踪器）

功能：追踪 LLM 调用次数、token 用量，估算费用

关键方法：estimate_tokens(), add_call(), get_summary()

潜在调用方：LLM 代理/循环模块（如主执行循环）

调用模式：每次 LLM 请求前后记录 token

2. ToolResult （结构化工具结果）

功能：封装工具执行结果（成功/失败/错误类型/重试建议）

关键方法：to_llm_feedback(), from_raw()

潜在调用方：工具执行引擎

调用模式：每个工具调用后实例化

3. ContextManager （上下文窗口管理器）

功能：监控 token 使用率，发出警告

关键方法：check(), get_status_message()

潜在调用方：主循环/LLM 调用前检查

调用模式：每次工具调用后检查

4. retry_with_backoff （指数退避重试）

功能：带重试机制的装饰器/函数

参数：max_retries=3, base_delay=2.0

潜在调用方：网络请求、文件操作等可能失败的场景

调用模式：包裹不可靠操作

5. truncate_result （长输出截断）

功能：截断超长工具输出（默认 20000 字符）

潜在调用方：工具输出返回前

调用模式：任何可能返回大量文本的工具

6. detect_error （错误检测）

功能：检测工具执行结果是否包含错误

关键工具分类：COMMAND_TOOLS, WRITE_TOOLS

潜在调用方：ToolResult.from_raw()

调用模式：每次工具执行后自动判定
